## 2. 資料評估（已實測）
- **點雲**：73,729 點，單一 draw call，整合顯示卡也能 60 fps。CSV 3.8 MB，瀏覽器解析約 50 ms，不需要先轉成二進位格式。
- **範圍**：只有 25 點落在官方範圍（118–124°E、20–27°N）外，外框以官方範圍為準，範圍外的點照樣顯示。
- **深度分布**：0–50 km 有 60,054 點（81%），50–150 km 有 12,299 點，150 km 以上有 1,376 點。色帶要在淺層分得比較細，才看得出參考圖那種紅、黃分層。
- **地形資料**：採用 AWS Open Data Terrain Tiles（Terrarium PNG，免 API key）。已實測：z6 圖磚 `6/53/27` 高程範圍 −6370 ～ 3545 m，同時包含陸地與海底地形，資料可用。
  - 授權：資料來源為 SRTM、GMTED、ETOPO1 等，頁面上要標示出處。

## 3. 坐標轉換
- **來源**：EPSG:4326（經緯度）。**目標**：3D 場景的局部平面坐標，單位 km。以 (121°E, 23.5°N) 為原點：
  - `x = (lon − 121) × 111.32 × cos(23.5°)`、`y = (lat − 23.5) × 110.57`、`z = −depth × 深度誇張倍率`
- 這是等距圓柱的局部近似。範圍邊緣（20°N／27°N）的東西向誤差約 ±3%，只用於視覺化可以接受。點雲和地形共用同一個轉換函式，保證兩者對齊。
- **地形**：Terrarium 圖磚是 EPSG:3857，前處理時重採樣成 EPSG:4326 的規則經緯網格，再交給上面的轉換函式。
- **垂直比例**：範圍寬約 600 km，陸地高度只有 4 km，地形要另外誇張（預設 ×10）才看得出起伏。地形倍率與深度倍率分開，各自用滑桿調整。

## 4. 架構
```
4-資料處理/
  build_terrain.py           # 前處理：下載 Terrarium z7 圖磚（約 12 張）→ 拼接 → 重採樣成 4326 網格 → terrain.bin + terrain.json
  eq-3d/                     # Vite + TypeScript strict + three.js（pnpm）
    public/data/             # EQHistory.CSV、terrain.bin（衍生資料，gitignore，用腳本複製）
    src/
      main.ts                # 組裝場景、載入資料
      geo.ts                 # 經緯度 → 局部 km（純函式，vitest）
      catalog.ts             # CSV 解析 → Float32Array（純函式，vitest）
      colormap.ts            # 深度色帶（純函式，vitest）
      layers/points.ts       # 點雲 mesh + shader
      layers/terrain.ts      # 地形 mesh
      layers/frame.ts        # 外框
      ui.ts                  # lil-gui 控制面板與圖例
```
- 相依套件：`three`、`lil-gui`，開發用 `vite`、`typescript`、`vitest`、`@types/three`。CSV 欄位固定且沒有引號，自己寫解析器（約 20 行）即可，不引入 papaparse。
- 篩選（規模、年份）用 uniform 傳進 shader，不符合的點在 shader 內 `discard`，拖動滑桿時不需要重建 buffer。
- `terrain.bin`：Int16 高程網格，約 600×700，大小約 840 KB。

## 6. 可行性結論
**可行。** 資料量、瀏覽器效能、地形資料來源都已實測沒有問題，沒有必須自行開發的高風險技術。

| 風險 | 影響 | 對策 |
|---|---|---|
| 半透明地形與點雲的繪製順序 | 點雲可能被地形遮住或閃爍 | 點雲設定 `depthWrite: false`，並明確指定 `renderOrder`（先畫地形再畫點雲） |
| 視覺效果和參考圖有落差 | 要多次調整 | 色帶、點大小、倍率都做成參數，T7 集中調校 |
| 外部圖磚來源異動 | 前處理失敗 | 只在前處理時下載一次，執行時不依賴外部服務；產出的 `terrain.bin` 可以保留 |
| 手機 GPU 效能 | 低階裝置會卡頓 | 原型先以桌機為目標；之後再視需要降低地形網格密度 |
