# 圖片轉 3D 點雲並放到台灣下方 — 實作計畫（評估）

> 任務單：`5-3D點雲/1-圖片點雲測試.md`
> 參考作法：`1-Plans/5-地震點雲整合網站實作計畫.md`（Vite + three.js 檢視器，用 iframe 嵌入 `/history`）

## 1. 目標
把一張 2D 圖片轉成帶顏色的 3D 點雲，賦予地理坐標（經度、緯度、深度），放在台灣下方的地殼裡，和地震點雲在同一個 3D 場景中顯示。

## 2. 測試圖片
- 原本附的 `girl.png` 不使用（原因見本次 session 的說明）。
- 換成中性的測試圖：物件、雕像、建築、風景，或非性感取向的人像都可以。整條處理流程和圖片內容無關，換圖不影響計畫。

## 3. 圖片 → 3D 的做法比較
| 方案 | 做法 | 產出 | 優點 | 缺點 |
|---|---|---|---|---|
| **A. 單張深度估計（建議先做）** | Python 用 Depth Anything V2（Hugging Face `transformers`）推估每個像素的深度，再把 (u, v, depth, RGB) 轉成點 | 2.5D 浮雕點雲：只有正面，每個點都帶原圖顏色 | 不需要 Blender；結果固定、可重現；本機 CPU 即可執行（Small 模型約 25M 參數）；點數可控 | 看不到背面，從側面看是一片有起伏的浮雕 |
| B. Blender MCP `generate_3d` | 用圖片生成完整 3D mesh → 在 Blender 的表面上取樣點 → 匯出 PLY 或 CSV | 360° 完整模型的點雲 | 立體感最好，可以繞著看 | 每次 1–3 分鐘，可能消耗額度；結果不一定可重現；Blender 要開著並連上 MCP（目前**未連線**） |
| C. 亮度當高度 | 灰階亮度直接當作 z | 浮雕 | 最簡單 | 深度和實際形狀無關，效果差 |

**建議：先做 A**，驗證整條流程（坐標轉換 → 檢視器 → 網站），再視需要用 B 換掉資料來源。兩者輸出的格式相同（見第 4 節），檢視器不用改。

## 4. 地理定位與資料格式
- **錨點（可調整）**：預設中心 121.0°E、23.5°N，深度 150 km；模型高度 150 km（垂直方向沿深度軸）。
- **坐標轉換**：模型的局部坐標（u, v, d）先正規化到 [-0.5, 0.5]，再轉成：
  - `lon = 121.0 + u × W / (111.32 × cos 23.5°)`
  - `lat = 23.5 + d × D / 110.57`（深度估計的 d 對應南北方向的厚度）
  - `depth_km = 150 − v × H`（圖片上方 = 較淺）
  - 最後的經緯度坐標系是 EPSG:4326。顯示時由檢視器現有的 `geo.ts` 轉成場景的 km 坐標，因此和地震點、地形完全對齊。
- **輸出**：`image-cloud.csv`，欄位 `x,y,z,r,g,b`。x=經度、y=緯度、z=−深度 km，和 `EQHistory.csv` 的慣例一致；r、g、b 為 0–255。
- **點數**：預設把圖片縮到長邊 300 px，約 6 萬點，和地震點雲同一個數量級，效能沒有問題。去背後的點數會更少。
- **去背**：背景像素（例如牆面、床鋪）會讓點雲變成一整片方塊。可以用 `rembg` 去背，或用深度門檻切掉遠處的背景。

## 7. 可行性
**可行。** 方案 A 的技術都很成熟，只要寫一支約 150 行的 Python 腳本，再加一個 three.js 圖層。

| 風險 | 對策 |
|---|---|
| 第一次要下載 PyTorch 和模型（約 1 GB） | 只在前處理時用，不進網站；`uv run --with` 執行時隔離環境 |
| 單張深度估計只有正面 | 這是方案 A 的本質；需要完整立體效果時改用方案 B |
| Blender MCP 目前未連線 | 方案 A 不需要 Blender；要做方案 B 時，請先開啟 Blender 並啟用 addon |
| 公開網站上出現與地震無關的圖層 | 預設關閉；或只在 `?debug` 參數下才顯示 |
